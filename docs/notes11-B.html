Review: Synchronization Primitives¶

Issue with Concurrency is that we need to perform synchronization.

Synchronization Primitives Problem Approach
Lock Race Condition Ownership
Condition Variables Busy Waiting, Deadlock Ownership
Semaphores Race Condition, Busy Waiting, Deadlock Signaling

Condition variables and semaphores can both help prevent deadlock in some cases, but they can also cause it as well.

These primitives are like malloc and free in data structures... they are low-level mechanisms for managing resources, but they don't tell us how they should be used. Therefore, we should study patterns.

Semaphores: Overview¶

A semaphore is a synchronization primitive that consists of an integer that we can manipulate with two operations:

def sem_wait(s):
    s.value--
    if s.value < 0:
        thread_wait()

def sem_post(s):
    s.value++
    if threads_waiting():
        threads_wakeup_next()

Semaphores combine the mutual exclusion of a lock and the signaling of a condition variable.

Observations: Typically we do locks and condition variables togather and semaphores separately (don't mix).

Reading 06: Rate-Limiting / Throttling¶

/* Global variables */

sem_t  Lock;
sem_t  Running;
size_t Failures = 0;

int main(int argc, char *argv[]) {
    /* Initialize Semaphores */
    sem_init(&Lock, 0, 1);
    sem_init(&Running, 0, MAX_THREADS);

    /* For each argument, create thread to compute sha1sum */
    pthread_t thread[argc - 1];

    for (int i = 1; i < argc; i++) {
        // Discuss: mq_start
        pthread_create(&thread[i - 1], NULL, sha1sum_thread, argv[i]);
    }

    /* For each argument, join thread */
    for (int i = 1; i < argc; i++) {
        pthread_join(thread[i - 1], NULL);
    }

    return Failures;
}

void *sha1sum_thread(void *arg) {
    sem_wait(&Running);

    char cksum[SHA_DIGEST_LENGTH*2 + 1];
    char *path = (char *)arg;

    if (!sha1sum_file(path, cksum)) {
        sem_wait(&Lock);
        Failures++;
        sem_post(&Lock);
    } else {
        printf("%s  %s\n", cksum, path);
    }

    sem_post(&Running);
    return NULL;

}

Observations:

  • Critical section is region with shared data (Failures)

  • Semaphores have an implicit queueing system (ie. waiting)

  • Can use only one semaphore by:

    • Guard thread_create with Running
    • But still have dead threads that haven't joined... perhaps pthread_detach to allow the threads to cleanup automatically when they exit
    • Return failures to get rid of Lock

Semaphores: Reader-Writer Locks¶

With semaphores, we can create interesting synchronization objects such as reader-writer locks:

  • Once readers acquire the writelock, as many readers as possible can read the data.

  • Once a writer acquires the writelock, no one else can access the data.

  • Unfortunately, this can add overhead and is prone to starvation.

Example: databases, GrubHub.

Semaphores: Reader Preference¶

size_t Readers    = 0
sem_t  WriterLock = 1
sem_t  ReaderLock = 1

Writer():
    sem_wait(&WriterLock)
    do_write()
    sem_post(&WriterLock)
  • Pro: Allows multiple readers
  • Con: Writer may starve
Reader():
    sem_wait(&ReaderLock)
    if Readers == 0:
        sem_wait(WriterLock)
    Readers++
    sem_post(&ReaderLock)

    do_read()

    sem_wait(&ReaderLock)
    Readers--
    if Readers == 0:
        sem_post(WriterLock)
    sem_post(&ReaderLock)

Semaphores: Fair¶

size_t Readers      = 0
sem_t  WriterLock   = 1
sem_t  ReaderLock   = 1
sem_t  ServiceQueue = 1     //

Writer():
    sem_wait(&ServiceQueue) //
    sem_wait(&WriterLock)
    sem_post(&ServiceQueue) //
    do_write()
    sem_post(&WriterLock)

Reader():
    sem_wait(&ServiceQueue) //
    sem_wait(&ReaderLock)
    if Readers == 0:
        sem_wait(WriterLock)
    Readers++
    sem_post(&ServiceQueue) //
    sem_post(&ReaderLock)

    do_read()

    sem_wait(&ReaderLock)
    Readers--
    if Readers == 0:
        sem_post(WriterLock)
    sem_post(&ReaderLock)

Semaphores: Summary¶

Semaphores are another useful and flexible synchronization primitive:

  • Good when you need a barrier or want to have bounded access to a resource.

  • Unlike locks and condition variables, there is no notion of ownership.

  • Can avoid using locks and condition variables if desired.

Mutex Lock
Cond  Dancing

# Threads

def thread_you_dance():
    mutex_lock(Lock)
    while Friends < MIN_FRIENDS:
        cond_wait(Dancing, Lock)
    mutex_unlock(Lock)

    dance()

def thread_friend_dance():
    mutex_lock(Lock)
    Friends++
    cond_signal(Dancing)
    mutex_unlock(Lock)

    dance()

Semaphore Lock     = 1

def thread_you_dance():
    sem_wait(Dancing)

    dance()

    sem_wait(Lock)
    Friends++
    if Friends == MIN_FRIENDS:
        sem_post(Dancing)
